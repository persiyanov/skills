# Encode Lessons in Structure

Change what allows a recurring mistake, because a type, a shared operation, or an automated check removes the need to remember a rule every time.

First work out what generalizes. One example or preference isn't automatically a universal rule. Put the fix where the knowledge belongs, and choose a mechanism that prevents the actual mistake without burdening unrelated work.

For example, after a third review flags a component with no loading state, make the loading state a required part of the component's type, so the build fails without it. A fourth reminder in the review checklist would only wait for the fourth miss.

Remove the instructions that the fix made redundant, but keep the explanations that people still need. When the decision needs judgment, write a short principle instead of piling up exceptions and process steps.

Acknowledging a lesson doesn't make it stick. Make the authorized change, or propose it clearly.

Ask: What prevents the same mistake next time?
