# Paper

Use one page per piece of work, named after the target and the start date, laid out so that the user knows where to look without reading anything.

- **At the start of every session,** make the file's tokens match the product's theme, read from the repo's token files on the main branch, because other work may have changed them: compare them with `get_tokens`, and fix each difference with `set_tokens`, leaving the work's own set of new values as it is.
- **Top:** the design as it is now, at full size and side by side, in each state that people meet, with today's version on the left when there is one. It's the one place the user needs to look, so keep it current.
- **Forks:** below it, one row per fork, named `Fork <n> · <part>`: the options side by side in their place, the pick marked, and one line each on the trade-off and on what switching it would change.
- **Versions:** before you fix a review's findings, duplicate the reviewed artboards, named `Reviewed · <date>`. When the user switches a fork, the new version goes beside the old one. Leave earlier versions as they are, because they're the record.
- **References:** one artboard, with each best product's screenshot, its source and one line on what it decided.
- **Notes:** a note sits beside the part it's about, because people connect a note to its part only when the two sit together (Ginns, 2006). Give markers a neutral color, because red marks a failure.
- **Drawing:** move each new artboard into place, and name it when you create it, because renaming truncates names to 50 characters. Paper drops some styles without an error, such as `left` and `top` on a new artboard, the base color of a `background` shorthand, camelCase properties in `write_html`, and an SVG's `stroke-opacity`, so read the result back with `get_computed_styles`. Draw screens as layers bound to tokens, so that they can be measured. To try new values, add a set of tokens for the work and bind only the new frames to it, which leaves earlier frames and other pages as they were. Nest the frames as the groups that people should see, with padding inside a box and gaps between its children (Figma Learn, "Guide to auto layout"; Braid, "Layout").
